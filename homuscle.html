Overview

"몇 개 했더라?" — 홈트의 가장 사소하고 집요한 문제

집에서 덤벨 운동을 하다 보면 횟수를 세는 일이 생각보다 큰 방해가 됩니다. 세다가 놓치고, 놓치면 대충 넘어가고, 대충 넘어가면 기록이 안 남고, 기록이 없으면 꾸준함도 무너집니다. 직접 겪은 이 문제를 카메라 포즈 인식으로 풀 수 있겠다는 가설에서 프로젝트를 시작했습니다.

HOMUSCLE은 웹캠 앞에서 운동하면 팔꿈치 각도를 실시간으로 추적해 횟수를 자동으로 세고, 기록하고, 스트릭으로 동기를 유지시키는 웹앱입니다. 별도 앱 설치도, 서버도, 계정도 없습니다 — HTML 파일 하나가 전부입니다. 디자이너로서 기획·디자인 시스템·모션·카피를 정의하고, AI(Claude)와의 바이브 코딩으로 구현까지 직접 완성했습니다.

Design System

블랙 + 단 하나의 포인트 컬러

프리미엄 스포츠 브랜드의 공간 경험을 레퍼런스로, 완전한 블랙 배경 위에 주황(#FF6B00) 단일 액센트라는 강한 제약을 스스로 걸었습니다. 색이 하나뿐이면 위계는 온전히 타이포그래피와 여백이 만들어야 합니다 — 운동명은 4~5rem 초대형 올캡스로, 레이블은 0.72rem 올캡스 + 넓은 자간으로, 카운터는 7rem 주황으로. 주황은 "지금 중요한 것"에만 절제해서 씁니다.

모든 색은 CSS 변수 토큰으로만 사용하도록 규칙화해, AI와 협업하며 화면이 늘어나도 시스템이 흐트러지지 않게 했습니다.

Key Screens

화면이 아니라 앱을 그대로 담았습니다

아래 화면들은 전부 실제 앱이 라이브로 임베드된 것입니다. 상단 탭을 눌러 화면을 옮겨 다니거나, 목표를 추가해볼 수도 있습니다.

01 · Training — 오늘의 목표와 동기

모토·스트릭·통계·목표 카드를 한 화면에 배치했습니다. D-day 숫자는 주황으로 압도적으로 크게 — "오늘 해야 하는 이유"가 화면에서 가장 먼저 읽히도록 설계했습니다. 목표를 달성한 날에도 "계속 하기"로 재운동이 가능하게 해, 달성 뱃지가 운동을 멈추는 핑계가 되지 않게 했습니다.

TRAININGLIVE

02 · Gallery — 기록이 쌓이는 곳

달력에서 운동한 날은 주황 도트로, 인증샷이 있는 날은 썸네일로 표시됩니다. 날짜를 클릭하면 그날의 모든 세션이 우측 패널에 나타나고, 기록 카드를 누르면 상세 모달이 슬라이드업됩니다. 기록을 "다시 보고 싶은 것"으로 만드는 것이 리텐션 설계의 핵심이었습니다.

GALLERYLIVE

03 · Stretch — 모션 가이드를 직접 설계

목·어깨 스트레칭 가이드는 영상 대신 SVG 와이어프레임 애니메이션으로 직접 제작했습니다. 관절 회전축과 동작 궤적을 코드로 그리면 용량이 거의 없고, 브랜드의 블랙/주황 톤을 그대로 유지할 수 있습니다. 같은 방식의 애니메이션이 운동 시작 전 가이드 팝업에도 쓰입니다.

Session

운동 중에는 화면을 읽을 수 없다

세션 화면의 제약 조건은 명확했습니다 — 사용자는 화면에서 2~3m 떨어져 있고, 두 손에는 덤벨이 들려 있습니다. 그래서 풀스크린 카메라 위에 최소한의 정보만 올렸습니다: 7rem 주황 카운터(멀리서도 읽히는 유일한 숫자), 풀와이드 진행 바, 그리고 포즈 스켈레톤 오버레이. 모든 조작은 세션 전후로 밀어냈고, 세션 중 피드백은 시각(펄스)과 청각(사운드)으로 이중화했습니다.

아래는 세션 화면의 구조를 재현한 목업입니다 — 실제 세션은 카메라 권한이 필요해 라이브 앱 ↗에서 체험할 수 있습니다.

카운팅 상태머신 — 관대함이 UX다

초기 버전은 팔을 50° 이하로 완전히 굽혀야 카운트됐고, 직접 운동해보니 정확한 자세보다 "안 세지는 억울함"이 이탈 요인이었습니다. 임계값을 몸으로 튜닝해 80°/110°로 완화하고, 노이즈 오카운트는 프레임 안정화와 디바운스로 막았습니다.

Feedback & Motivation

카운팅은 기능, 꾸준함은 디자인

자동 카운팅만으로는 습관이 만들어지지 않습니다. 운동 전·중·후 각 단계의 감정에 맞는 피드백 장치를 배치했습니다.

운동 전 · 가이드 팝업
세션 진입 시 SVG 모션 가이드로 정확한 자세를 먼저 각인 — 잘못된 자세로 인한 미카운트 예방
운동 중 · 펄스 + 사운드
카운트마다 손목 주변 주황 펄스와 사운드가 동시에 반응 — 화면을 안 봐도 "세졌다"를 확신
운동 중 · 격려 메시지
진행률 구간마다 풀스크린 격려 문구 오버레이 — 마지막 반복의 고비를 넘기는 장치
완료 · 컨페티

Process — Working with AI

스펙 문서가 곧 디자인 산출물

바이브 코딩에서 결과물의 품질은 프롬프트가 아니라 스펙의 정밀도가 결정한다는 것을 배웠습니다. 디자인 시스템 토큰, 레이아웃 규칙, 인터랙션 임계값, 완성 기준 체크리스트까지 담은 474줄짜리 스펙 문서(HOMUSCLE.md)를 먼저 쓰고, AI에게는 "그려달라"가 아니라 "이 시스템을 구현하라"고 요청했습니다. 별도의 운영 문서(CLAUDE.md)에는 어떤 AI 모델이 작업해도 품질이 유지되도록 불변식과 검증 절차를 고정했습니다.

Reflection

배운 것과 다음 단계

📐
Learning #1
임계값은 데이터가 아니라 몸으로 찾았다
"정확한 인식"보다 "안 세지는 억울함 제거"가 실제 UX를 결정했습니다. 인터랙션 파라미터도 사용자 리서치의 대상이라는 것을 체감했습니다.
🛡
Learning #2
신뢰는 성공 케이스가 아니라 실패 처리에서 만들어진다
모델 로드 실패, 포즈 미검출, 저장 초과 — 모든 실패 경로에 폴백을 설계하고 나서야 "믿고 운동할 수 있는" 도구가 됐습니다.
📄
Learning #3
AI 시대 디자이너의 산출물은 스펙의 정밀도
같은 AI라도 스펙 문서의 해상도에 따라 결과물이 완전히 달라졌습니다. 토큰·규칙·체크리스트로 시스템을 문서화하는 능력이 곧 구현 품질이 됐습니다.
